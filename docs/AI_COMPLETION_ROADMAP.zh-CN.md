# BLACK SOULS AI 自主通关详细路线图

本文档是项目后续工作的唯一进度清单。能力设计以
`docs/AUTONOMOUS_COMPLETION_SPEC.zh-CN.md` 为准，本文件负责记录实施顺序、完成条件和真实测试结果。

## 更新规则

完成任何一项工作时必须同时执行：

1. 将对应项目由 `[ ]` 改为 `[x]`；
2. 在项目下方增加 `完成说明`，写明实际结果；
3. 写明验证方法与验证结果，不能只写“已完成”；
4. 在文末“进度记录”中追加日期、任务编号、结果和下一项；
5. 如果实现与原计划不同，先修正文档，再记录实际完成的方案；
6. 一次只把一个最小任务标记为“正在进行”，失败或受阻时保留现场证据；
7. 涉及真实游戏、存档或脚本前，先完成对应备份任务。

## 状态总览

- 当前阶段：规划完成，准备进入 P0-A 基线与游戏脚本调查
- 总体目标：从全新存档开始，由 AI 自主完成任意一个主线结局
- 当前完成度：规划 6/6 项；全部清单 6/290 项（约 2%）
- 当前进行中：无
- 下一项：`P0-A01` 记录项目、游戏、桥接和存档基线
- 开始门槛：确认本轮允许进入实施后，再执行任何代码、游戏脚本或存档改动
- 最终验收：结局由至少两类游戏内证据确认，并能从终局前备份重复关键尾段

## 执行原则

- 按“观察 → 判断目标 → 操作 → 验证 → 失败恢复”构建完整闭环。
- 先消除“看不见”和“死后接不上”的问题，再追求自动寻路和复杂战术。
- 游戏内桥接只提供事实和受限输入；路线判断、循环检测及长期记忆放在自主运行层。
- 内置资料按需检索，不在启动时整体放入模型上下文。
- 联网资料先进入候选区，记录来源并经过游戏内验证后再转为正式资料。
- 游戏操作通过正常输入完成，不直接修改金币、物品或剧情进度。
- 所有列表、文本、日志和事件记录必须有上限、分页或裁剪标记。
- “命令已处理”和“游戏目标已达成”必须分开判断。
- 五日安排是阶段顺序，不以牺牲基线、备份或验证来赶日期；P0 未通过时不进入无人值守测试。

## 启动工作包

实际开始工作时按以下顺序推进，不同时展开多个会改动相同文件的任务：

1. **工作包 1：基线与保护**
   - 范围：`P0-A01` 至 `P0-A09`。
   - 结果：得到当前环境记录、完整备份、基线检查结果和回滚方法。
   - 限制：这个工作包不修改项目功能，也不启动会改变存档的实机测试。
2. **工作包 2：静态调查**
   - 范围：`P0-A10` 至 `P0-A24`。
   - 结果：得到真实场景、窗口、输入、战斗、死亡、存档和进度候选清单。
   - 限制：只读分析游戏脚本，调查结论必须区分已确认事实和推测。
3. **工作包 3：受控实机确认**
   - 范围：`P0-A25` 至 `P0-A31`。
   - 结果：用真实游戏修正静态分析结论，冻结第一批实现所需的数据结构。
   - 限制：先备份，逐项执行；死亡和恢复测试必须有明确回滚点。
4. **工作包 4：最小纵向闭环**
   - 从 P0-B 至 P0-F 中先完成“菜单可读、操作可验证、存档可恢复、运行可交接”的最小组合。
   - 每补完一项能力，立即增加合成测试；涉及真实状态的能力再增加对应实机验证。

“第 1 天”表示首先完成上述开发与预演门禁。若当天未通过 P0-F，下一工作日继续 P0，不提前开始第 2 天的正式新存档测试。
